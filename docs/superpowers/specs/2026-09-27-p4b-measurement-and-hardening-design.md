# P4b — Measurement Fixes and Boot-Apply Hardening

Date: 2026-09-27
Status: approved (design), not yet implemented
Parents: `2026-09-26-p3-search-and-journal-design.md`, `2026-09-26-p4-persistence-and-boot-apply-design.md`
Source: best-practice research of 2026-09-27 (kept outside the repo), items 1–6.

## 1. Goal

Fix the two places where the tuner's measurement is not trustworthy, and close the security
and reliability gaps of the elevated logon task — before the UI (P5) is built on top.

1. **Memory search measures stability only.** GDDR6X (EDR) and GDDR6 (EDC) retry failed
   transfers, so an excessive memory clock loses bandwidth without errors or crashes; the
   compute-bound matmul checksum cannot see it. On the RTX 4070 the search hit the top of its
   range (+1500) every run. NVAPI's memory offset is in the same unit as Afterburner's slider
   (hardware check 5: `--set-mem 100` moved NVML's memory clock 10501 → 10601), and a review
   found +1000 in Afterburner on a 4070 FE.
2. **One 3 s probe decides the edge; the margin is one step**, while the core edge moved 30 MHz
   between runs.
3. **The elevated logon task runs an exe from the user-writable build folder** and trusts config
   in `%LOCALAPPDATA%`.
4. **The elevated process writes (temp + rename) into a user-writable folder.**
5. **`schtasks /Create` defaults** do not start the task on battery and allow 72 h runtime.
6. **`d3dcompiler_47.dll` is an implicit import**, not a KnownDLL, so the exe's folder is searched
   first.

Success criteria:
- The memory search stops at the bandwidth peak, not at the stability ceiling, and the log shows
  GB/s per step.
- Every applied core and memory offset derives from an edge that passed a 30 s probe.
- After `--boot on`, the task runs `%ProgramFiles%\GpuAutoOptimizer\gao.exe`, all state lives in a
  protected `%ProgramData%\GpuAutoOptimizer\`, and the task starts on battery.
- A planted `d3dcompiler_47.dll` next to the exe is not loaded.
- New decision logic (bandwidth scan, confirmation, task XML) is unit-tested in CI.

## 2. Decisions

| Decision | Choice | Why |
|---|---|---|
| Edge reliability | **Confirm with 30 s probes** after the fast search; step down on failure; margin applies to the confirmed edge | "Search fast, confirm long" is the vendor pattern; costs ~1–2 min. User-approved. |
| Memory criterion | Highest **bandwidth**, not highest stable offset | Error replay turns instability into lost bandwidth. |
| Memory search shape | Linear upward scan, 50 MHz steps | Bandwidth rises then falls; binary search needs monotonicity. |
| State location | Everything (`gao.json`, journal, `boot.log`) in `%ProgramData%\GpuAutoOptimizer\` with a protected DACL | Every writer is already elevated; the elevated process then never writes where a user can plant junctions. |
| Install | `--boot on` copies the exe to `%ProgramFiles%\GpuAutoOptimizer\`; the task points there | Admin-only-writable, as Afterburner does it; no installer needed. |
| Task definition | XML via `schtasks /Create /XML`, generated by a pure `core` function | Only way to set battery/time-limit/instances without the COM API; testable. |
| Migration | Old journal is imported once; old profile is not | Freeze ceilings stay valuable; the profile is invalidated by the new memory method anyway. |

## 3. Bandwidth measurement (`hw/stress`)

- Two `RWByteAddressBuffer`s of 256 MB each (well above the 4070's 36 MB L2).
- A copy compute shader: each thread copies `uint4`s in a grid-stride loop, `dst[i] = src[i]`.
- Timing: `D3D11_QUERY_TIMESTAMP_DISJOINT` + two `D3D11_QUERY_TIMESTAMP`s around N dispatches.
  `GB/s = 2 × bytes × N / seconds / 1e9` (read + write).
- `Stress::MeasureBandwidth()` returns the median of 3 runs of ~0.3 s each, or a device-lost
  flag. Buffers are created lazily on first use and released with the device.

## 4. Search changes (`core/search`)

### 4.1 Memory: bandwidth scan

```cpp
struct MemSample { bool stable = false; double gbps = 0; };
// Scans lo, lo+step, ... (<= hi, < ceiling). Stops at the first unstable sample, or when gbps
// falls more than kBandwidthDrop (1 %) below the best so far. lo is measured too (it is the
// reference). Returns the LOWEST stable offset whose gbps is within kBandwidthTie (0.5 %) of
// the best seen, so measurement noise on a flat curve never drifts the result upward.
int best_bandwidth_offset(int lo, int hi, int step, int ceiling,
                          const std::function<MemSample(int)>& sample);
```

Per candidate (journaled like every clock candidate): set state → 3 s stability probe → if
STABLE, `MeasureBandwidth()`. The log line adds `bw=… GB/s`. `OptimizeIo` gains
`std::function<std::optional<double>()> bandwidth` (nullopt = device lost / not available); when
it is empty (tests, or a failure), the memory step falls back to the P3 stability-only search.

### 4.2 Confirmation

```cpp
// Confirms `edge` with a long probe; on failure steps down by `step` and retries, at most
// kConfirmTries times, never below lo. Returns the confirmed value (lo if none held).
int confirm_edge(int edge, int lo, int step, const std::function<bool(int)>& holds);
```

Core: `holds(v)` = 30 s probe at core `v`, mem 0. Memory: 30 s probe at the chosen core and mem
`v`. Both journaled. Then `apply_margin(confirmed, step, perf_push)` as before, and the soak as
before. `OptimizeResult` gains `core_confirmed` and `mem_confirmed`.

Constants: `kConfirmProbeS = 30`, `kConfirmTries = 3`, `kBandwidthDrop = 0.01`, `kBandwidthTie = 0.005`,
`kBandwidthRuns = 3`.

## 5. State, install and task (`hw/app_files`, `hw/boot_task`, `core/task_xml`)

### 5.1 Protected state folder

- `app_dir()` becomes `%ProgramData%\GpuAutoOptimizer`.
- `ensure_app_dir()` (called by every elevated command before writing): create the folder with
  SDDL `O:BAD:P(A;OICI;FA;;;SY)(A;OICI;FA;;;BA)(A;OICI;0x1200a9;;;BU)` — owner Administrators,
  protected (no inheritance), SYSTEM and Administrators full control, Users read & execute. If
  the folder exists, its owner must be `BUILTIN\Administrators` or `NT AUTHORITY\SYSTEM`,
  otherwise refuse with a message naming the folder; then re-apply the DACL.
- `--status` only reads and works without elevation.
- Migration: when `journal.jsonl` does not exist in the new folder and
  `%LOCALAPPDATA%\GpuAutoOptimizer\journal.jsonl` does, its lines are appended once (they are
  parsed as untrusted data like any journal). The old folder is left alone.

### 5.2 Installed copy

- `--boot on`: create `%ProgramFiles%\GpuAutoOptimizer\` and `CopyFileW` the running exe there
  (overwrite), unless the running exe already is that path.
- `--boot off`: delete the task, the installed exe and the folder if empty.
- `--status`: `boot copy: up to date | OUTDATED (run gao --boot on) | not installed`, comparing
  size and content hash (FNV-1a over the bytes) of the build and the installed copy.

### 5.3 Task XML

```cpp
// Task Scheduler XML (the caller writes it as UTF-16LE with BOM). Paths are XML-escaped.
std::string boot_task_xml(const std::string& exe_path_utf8, const std::string& user_id);
```

Contents: `LogonTrigger` for `user_id` with `<Delay>PT15S</Delay>`; `Principal` with
`LogonType InteractiveToken`, `RunLevel HighestAvailable`; `Settings` with
`DisallowStartIfOnBatteries false`, `StopIfGoingOnBatteries false`,
`ExecutionTimeLimit PT5M`, `MultipleInstancesPolicy IgnoreNew`; `Exec` with the quoted path and
`--boot-apply`. Task name `\GpuAutoOptimizer\BootApply`. The XML file is written into the
protected state folder, loaded with `schtasks /Create /TN \GpuAutoOptimizer\BootApply /XML <file>
/F`, then deleted. `--boot on` and `--boot off` also delete the legacy task `\GpuAutoOptimizer`.

## 6. DLL loading

- First statement of `main`: `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)`.
- Link `gao` with `/DELAYLOAD:d3dcompiler_47.dll`, `delayimp.lib`, and
  `/DEPENDENTLOADFLAG:0x800`.

## 7. Testing

Unit tests (CI):
- `best_bandwidth_offset`: rises-then-falls curve → peak; unstable step → stops, best before it;
  flat within noise → the lowest offset reaching the best (no drift upward on noise); ceiling
  respected; lo is sampled.
- `confirm_edge`: holds at edge; fails once → one step down; fails always → lo after 3 tries;
  never below lo.
- `optimize()` with the fake card extended by a bandwidth curve: memory result = bandwidth peak
  (not the stability edge); confirmed values reported; margin applied to confirmed values;
  journal has no open entries; fallback to stability-only when `bandwidth` is empty.
- `boot_task_xml`: contains each setting; escapes `&`, `<`, `>`, `"` in the path; quotes the path.

New rows in `docs/hardware-checks.md`:

| # | Check | Expected |
|---|---|---|
| 23 | `--optimize best` memory scan | log shows GB/s per step; result is the bandwidth peak |
| 24 | Confirmation | 30 s confirm lines for core and memory; margin applied to confirmed edges |
| 25 | `--boot on` | exe in `%ProgramFiles%\GpuAutoOptimizer\`; `schtasks /Query /TN \GpuAutoOptimizer\BootApply /XML` shows the settings; log off/on → `applied` |
| 26 | State folder ACL | `icacls "%ProgramData%\GpuAutoOptimizer"` shows the protected DACL; `--status` works unelevated |
| 27 | DLL planting | a dummy `d3dcompiler_47.dll` beside the exe is not loaded; `--stress 5` still STABLE |
| 28 | Migration | ceilings from the old `%LOCALAPPDATA%` journal are present after the first elevated run |

## 9. Revisions after review (2026-09-27)

- **No journal migration.** Reading `%LOCALAPPDATA%\...\journal.jsonl` from the elevated process
  could be redirected (junctions, object-manager links) to copy other files into the
  user-readable state folder. The old journal on the reference machine had no open entries.
- **Known folders, not environment variables**, for ProgramData and Program Files: `HKCU\Environment`
  is user-writable and would otherwise decide where the elevated process installs and writes.
- **Existing state folder is checked through one handle** opened with
  `FILE_FLAG_OPEN_REPARSE_POINT`; a reparse point is refused, owner check and DACL change use
  that handle (no junction adoption, no check/use race). `--apply` verifies the folder too.
- **Static CRT and delay-loaded `d3d11`/`dxgi`** in addition to `d3dcompiler_47`: every static
  import is now a KnownDLL.
- **Confirm probes treat TOO HOT as holding**; heat is handled by the power step and the soak.
- **`kBandwidthTie` = 1 %** (noise ~0.4 % vs ~0.5 % per step); the bandwidth source buffer is
  filled with pseudo-random data; the bandwidth resources are created all-or-nothing.
